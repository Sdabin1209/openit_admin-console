# ADR 0029: 사람 인증 화면은 게이트웨이의 OIDC 규약만 안다

- 상태: 채택(2026-11-03, U82). 설계 정본: 헤드 ADR 0014(사람 계정은 Keycloak과 OIDC로 관리한다). 이 문서는 화면 쪽 결정만 적는다.

## 맥락
사람 인증이 게이트웨이 basic_auth에서 oauth2-proxy(OIDC, Keycloak) forward_auth로 바뀐다. 게이트웨이는 신원을 `X-Openit-User`, 역할을 `X-Openit-Roles`로 판정하고, 새 계정(역할 없음)에는 403 `details.reason=ACCOUNT_PENDING_APPROVAL`을 준다. 이 콘솔은 자격을 입력받는 코드가 원래 없었다(게이트웨이가 브라우저 기본 인증 창을 띄웠다). 제거할 basic_auth 전제 코드는 코드에 없고, 문서 문구("게이트웨이가 인증한 계정")는 그대로 맞다.

## 결정
- 로그인은 `/oauth2/start?rd=<현재 경로>` 링크, 로그아웃은 `/oauth2/sign_out?rd=<Keycloak 로그아웃 URL>` 링크다. 비밀번호 입력란은 없다.
- 오류 분류(`link_http_send`): 401 -> `UNAUTHENTICATED`, 403이면서 `details.reason == ACCOUNT_PENDING_APPROVAL` -> `ACCOUNT_PENDING`. 사유는 문자열 검색이 아니라 `details.reason`으로만 구분한다(HTTP.md D69와 같은 방식). 그 밖의 403은 지금처럼 역할 부족(`PERMISSION_DENIED`)이다.
- 어느 클라이언트의 요청이든 이 두 오류를 받으면 알림 선(`onAuthError`)으로 진입점에 전해 화면 전체를 로그인 안내 또는 "가입 승인 대기 중" 화면으로 바꾼다. 화면마다 따로 처리하지 않는다.
- 현재 사용자·역할은 `GET /oauth2/userinfo`(oauth2-proxy 표준: email, user, groups)로 읽어 머리에 보인다. groups가 비면 승인 대기로 본다(ADR 0014 결정 4).
- admin 그룹이면 "계정 승인" 링크(`/auth/admin/openit/console/#/openit/users`, Keycloak 표준 관리 화면)를 새 창으로 연다. 승인 화면은 만들지 않는다(0014 결정 5).
- 로그인 이동은 자동 리다이렉트가 아니라 안내와 링크다.

## 왜
- OIDC와 oauth2-proxy의 표준 엔드포인트(`/oauth2/start`, `/oauth2/sign_out`, `/oauth2/userinfo`)만 쓰면 이 화면은 IdP를 모르고, 영역 사이는 게이트웨이 규약으로만 만난다(구조 규칙 1).
- 자동 리다이렉트를 안 하는 이유: 로그인이 끝나도 계속 401이면(설정 오류) 무한 이동한다. 안내를 보이면 사람이 원인을 볼 수 있다. 측정은 하지 않았다.
- 모든 요청의 인증 오류를 한 곳에서 받는 이유: 세션이 화면을 쓰는 도중 만료되면 어느 화면의 요청이든 먼저 401을 받는다.

## 검토한 대안과 버리는 이유
- 화면에서 자격을 받아 직접 인증: 비밀번호 저장·재설정·기록을 만들게 된다(0014).
- Keycloak 관리 API로 승인 화면 구현: 브라우저에 관리 토큰이 필요하고 같은 기능의 재구현이다(0014).
- `X-Openit-Roles`를 화면이 읽기: 브라우저는 요청 헤더가 아니라 응답만 본다. 역할 표시는 userinfo의 groups로 하고, 판정은 게이트웨이가 한다. 화면은 권한을 판단하지 않는다.

## 결과
- 얻는 것: 로그인·승인 대기·로그아웃·계정 승인 진입이 표준 경로로 닫힌다.
- 감수하는 것: Keycloak 로그아웃 URL은 헤드가 확정한 값(`/auth/realms/openit/protocol/openid-connect/logout?client_id=openit-gateway&post_logout_redirect_uri=<origin>/`)이다. 실제 IdP와의 흐름은 시험하지 않았다(모의 서버만).

## 되돌리는 조건
deploy 규약이 경로나 승인 대기 본문을 바꾸면 `components/session_view.ts`의 상수와 오류 분류만 고친다.
