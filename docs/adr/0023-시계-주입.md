# ADR 0023: 컴포넌트는 시계를 주입받는다

- 상태: 채택(U422, 2026-10-31).

## 맥락
`link_http_send`는 응답 본문을 다 읽을 때까지 시간 제한을 걸고, 기본값으로 전역 `setTimeout`을 직접 불렀다. 시험이 시간 초과를 보려면 실제로 기다리거나 시험 쪽에서 우회해야 했다. 시험의 합격·불합격이 기계가 바쁜 정도에 달리면 그 시험은 아무것도 확인하지 못한다.

## 결정
- `link_http_send`는 `Timers {set, clear}`를 필수로 주입받는다(전역 타이머 기본값 제거). 실제 타이머는 연결부 `app/wiring/gateway.ts`가 넣고, 시험은 가짜 시계(시험이 `fire()`를 부를 때만 만료)나 만료하지 않는 시계를 넣는다.
- 시험은 (a) 타이머에 넘어온 제한 값(`ms`)을 직접 단언하고 (b) 가짜 시계가 만료를 알릴 때 `UNAVAILABLE`·재시도 가능·타이머 해제를 확인한다. 실제 시간을 재지 않는다.
- 모의 서버의 느린 응답은 시간 지연이 아니라 시험이 쥔 문(`slowGate`)으로 한다.
- 시험의 유일한 바깥 마감은 `HANG_GUARD_SECONDS = 300`(`tests/helpers.ts`)이다.

## 왜
- 따른 표준: 의존성 주입(시계를 인자로). 와이어 형식·HTTP 요청/응답·화면 문구는 그대로이고 기존 시험이 전부 통과한다.

## 검토한 대안과 버리는 이유
- 전역 패치(`mock.timers` 등)로 `setTimeout`을 바꾸기: 컴포넌트가 전역에 기대는 채로 남고, 블로킹 대기를 못 움직인다. 주입이 더 단순하다.
- 상한을 늘리기: 덜 깨질 뿐 고친 것이 아니다.

## 결과
- 얻는 것: 시험의 실제 대기 0, 부하와 무관한 결과. 감수하는 것: 호출자가 시계를 넘겨야 한다(연결부 한 곳). 300초 값은 측정하지 않았다.

## 되돌리는 조건
없음(표준 관행).
