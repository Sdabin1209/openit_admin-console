# ADR 0010: 요청 시간 제한과 목록 한도 상수

- 상태: 채택하되 **값의 근거는 측정이나 문서에 없다**. 2026-10-29: 값의 출처 분류와 빠진 값은 [ADR 0016](0016-값의-출처-분류.md)이 이어받는다. 20쪽 초과 시 동작은 [ADR 0013](0013-목록-상한-초과는-오류.md)이 대체했다.

## 맥락
HTTP 요청이 멈추면 화면이 무한 대기하므로 상한이 필요하고, 목록은 쪽 단위로 읽는다.

## 결정과 근거 상태
| 상수 | 값 | 위치 | 근거 |
| --- | --- | --- | --- |
| 요청 시간 제한 | 15000 ms (응답 본문을 다 읽을 때까지 적용) | `app/components/link_http_send.ts`(값은 `app/wiring/gateway.ts`가 넣는다) | 값의 근거 기록 없음(측정 안 함). 본문까지 적용하는 이유는 헤더만 오고 본문이 멈추는 경우를 막으려는 것(전수 점검 지적). 시간 제한은 주입 가능해 시험은 가짜 시계를 쓴다. |
| 승인 목록 쪽 크기 | 100 | `app/components/link_gate_list_awaiting.ts` | 계약 HTTP.md 공통 목록 규칙의 limit 기본값 100과 같다(제약에서 온 값. 이 표를 처음 쓸 때는 계약의 기본·최대 값을 확인하지 못해 "서버 상한은 계약에 없다"고 잘못 적었다, 2026-10-29 정정: 기본 100, 최대 500). |
| 릴리스 목록 쪽 크기 / 최대 쪽 수 | 500 / 20 | `app/components/link_release_list.ts`, `link_failure_list.ts` | 근거 기록 없음. 최대 쪽 수는 서버 오류로 끝없이 읽는 것을 막는 안전 상한으로만 둔 것이며 실제 릴리스 수를 측정하지 않았다. 20쪽을 넘으면 오래된 릴리스가 목록에서 빠진다. |
| 보고서 해시 표시 길이 | 19자 (`sha256:` + 12자) | `app/ui/views.ts` | 사람이 눈으로 대조하는 용도의 앞부분이다. 길이 선택의 근거 기록 없음. 전송 값은 전체 해시이다. |
| 시험 매달림 감시 | 300초(`HANG_GUARD_SECONDS`) | `tests/helpers.ts` | 정상이면 즉시 끝나는 대기가 진짜로 멈췄을 때만 걸리는 바깥 마감. 측정 안 함. 판정이 아니다(U422, tests/TIMING.md). |

## 시간 사슬 (D119·D120, 확인: deploy ADR 0048의 값)
이 서버(Caddy 정적 파일)가 응답 머리글을 내기까지에는 설정된 시한도 상류 호출도 없다(`tests/exposure.test.ts`가 Caddyfile에서 고정). 게이트웨이의 `response_header` 상한은 10000ms(`deploy-exposure.json`)이고, 화면의 요청 시간 제한은 15000ms이다. 따라서 서버 < 게이트웨이(10000) < 화면 대기(15000)의 순서가 맞다. 이 비교는 설정 값끼리 한 것이며 실제 시간을 재지 않았다.

## 왜
위 값 중 측정·표준·제약에서 나온 것은 없다. 근거를 지어내지 않는다. 앞으로 운영에서 관찰된 값이 생기면 바꾼다.

## 되돌리는 조건
실제 게이트 응답 시간 분포나 릴리스 수를 측정하면 값을 그 근거로 바꾸고 이 표를 고친다.
