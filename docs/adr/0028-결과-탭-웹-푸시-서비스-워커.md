# ADR 0028: 결과 탭의 웹 푸시는 서비스 워커로 받는다

- 상태: 채택(2026-11-03, U92·L28, 계약 v3.4.0 PUBLIC_API B)

## 맥락
의사가 결과 화면을 닫아 두어도 새 문진 결과 도착을 알아야 한다. SSE(ADR 0026)는 화면이 열려 있을 때만 동작한다. 계약 3.4.0이 `GET /v1/staff/push-config`, `POST /v1/staff/push-subscriptions`(topics), 푸시 본문 `StaffPushPayload{kind: RESULT_READY, session_id}`를 정했다.

## 결정
- 결과 탭에 "웹 푸시 알림" 칸을 둔다: 켜기(권한 요청, 구독, 서버 등록 topics `["results"]`), 끄기(서버 해지 후 브라우저 해지). 서버 공개키가 null이면 꺼짐 안내만 보이고 SSE로만 알린다.
- 서비스 워커 `sw.js`는 페이지 번들과 따로 빌드한다(`app/sw.ts`). `push`에서 알림(tag `result-`+세션 ID)을, `notificationclick`에서 열린 콘솔 창을 앞으로 가져와 `#/results/{id}`로 이동(창이 없으면 새 창)한다. 알림 문구와 tag 규칙은 `push_notice`가 정한다.
- 서비스 워커 코드는 요청을 보내지 않는다(시험이 고정). 그래서 CSRF 규칙(Origin이 null이 될 전송 방식 금지)의 `serviceWorker` 금지는 등록 코드(`browser_push.ts`)만 예외로 한다.
- 204 본문 없음 응답을 받도록 `link_http_send`가 204의 빈 본문만 허용한다(해지 응답).

## 왜
- 화면이 닫힌 뒤에도 알리는 표준 수단이 W3C Push API + Notifications API + 서비스 워커다. 계약도 이것을 정했다.
- topics를 `results`로 고정한 이유: `alerts`는 staff 역할 몫이고 clinician이 보내면 403이다(계약). 이 콘솔은 의사용 결과 탭이다.
- 서버 해지를 먼저 하는 이유: 서버 호출이 실패하면 브라우저 구독을 남겨 다시 시도할 수 있다. 켜기에서 서버 등록이 실패하면 브라우저 구독을 되돌려, 켜졌다고 믿는 화면과 어긋나지 않게 한다.
- 알림 본문에는 세션 ID만 넣는다(계약: 환자 값·subject_ref 없음).

## 검토한 대안과 버리는 이유
- 폴링: 화면이 닫히면 못 받는다.
- 페이지 번들에 서비스 워커를 함께 묶기: 서비스 워커는 별도 스크립트 URL이어야 등록할 수 있다.

## 결과
- 얻는 것: 화면을 닫아도 도착 알림. 푸시가 꺼진 서버에서는 SSE로 그대로 동작.
- 감수하는 것: 실제 브라우저·푸시 서비스(FCM 등)와 서버 발송은 시험하지 않았다. 시험은 가짜 PushManager와 가짜 서비스 워커 범위, 모의 서버로 한다. 브라우저가 알림을 차단하면 켤 수 없다(안내만).

## 되돌리는 조건
계약이 푸시를 없애거나 본문 모양을 바꾸면 새 ADR로 대체한다.
