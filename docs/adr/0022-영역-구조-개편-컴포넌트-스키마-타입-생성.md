# ADR 0022: 영역 구조 개편 (컴포넌트, schemas/, 생성 타입, wiring)

- 상태: 채택(U400, 2026-10-30, 헤드 설계 규칙 D117 `head/docs/DESIGN.md`). 일부를 대체한다: ADR 0001의 디렉터리 배치(`api/`, `app/` 평면 배치), ADR 0017·0002의 생성물 위치(`generated/` -> `app/types/`). 생성 정책(커밋, 시험이 최신인지 확인)은 그대로다.

## 맥락
`api/`(클라이언트와 손으로 쓴 타입)와 `app/`(상태 기계, 모델, 뷰)가 섞여 있어, 업무 규칙(반려 사유 필수, 롤백 조건, 오류 문구)이 컨트롤러 안의 if와 함께 있었고, 손으로 쓴 응답 검사(`need(...)`)가 여러 곳에 있었다. 구조 규칙 6개(D104)와 D117은 영역을 "입력 스키마 -> 출력 스키마" 컴포넌트로 나누고 스키마를 진실의 전부로 삼으라고 한다.

## 결정
- 업무를 단계로 나눠 컴포넌트 24개(업무 12, 통신 12)로 정했다(`docs/components.md`). 업무 컴포넌트는 순수 함수이고 입력 검사는 스키마 검증이다.
- 내부 타입은 `schemas/`(JSON Schema 2020-12, 통과·거부 예시)에 두고, `app/types/`는 `scripts/gen-types.mjs`로 생성한다: 타입은 json-schema-to-typescript 15.0.4, 검증기는 Ajv standalone(CSP가 eval을 막으므로 런타임 컴파일 불가, ADR 0002). 계약 타입도 같은 도구로 고정 태그의 스키마에서 생성한다.
- 상태를 가진 것(진행 중 요청, 입력 중인 글)은 컴포넌트가 아니라 `wiring/`의 컨트롤러가 들고, 컴포넌트에는 입력을 넘겨 출력을 받는다(functional core, imperative shell).
- HTTP는 `link_*`에만 둔다. 계약 규약(BoundaryError 해석, 상태 코드 구분, retryable, 전송 한도)은 `link_http_send` 한 곳이다. 나머지 `link_*`는 그 컴포넌트를 import하지 않고 `HttpRequestSpec -> HttpOutcome` 함수를 wiring에게서 주입받는다.
- 화면 부품은 `wiring/ui/`에 둔다. 모의 서버는 시험 지원 코드라서 `tests/mock-server/`로 옮긴다.
- 응답은 계약의 닫힌 스키마가 아니라 화면이 읽는 부분의 읽기용 투영 스키마로 검사한다(ADR 0016·0017의 관대한 읽기 유지).

## 왜
- 따른 규칙: 구조 규칙 6개, DESIGN.md 2~6절(컴포넌트는 함수, 통신 컴포넌트, 스키마가 진실의 전부). 근거 문헌: functional core/imperative shell(Bernhardt), 포트·어댑터(Cockburn).
- 타입을 손으로 쓰면 스키마와 어긋난다(옛 `api/types.ts`는 계약을 손으로 옮긴 것이었다). 생성하면 `--check`로 어긋남을 시험이 잡는다.
- 읽기용 투영을 계약 사본으로 보지 않는 이유: 계약 `SubmissionView.status`는 닫힌 열거지만 설명이 "모르는 값은 그대로 보여 준다"이다. 닫힌 열거로 응답을 검사하면 서버가 값을 추가한 날 화면이 멈춘다.
- `ui/`를 `wiring/` 아래에 둔 이유: `head/scripts/structure-check.py`의 6번이 `components|wiring|types`와 진입점만 허용 위치로 안다. 헤드가 `ui/`를 추가하면 한 칸 올린다.

## 검토한 대안과 버리는 이유
- link 컴포넌트를 클라이언트 클래스 하나(`GateClient`)로 두기: "컴포넌트 하나 = 입력 스키마 하나 -> 출력 스키마 하나" 위반(메서드마다 입출력이 다르다). 작업(엔드포인트)마다 파일 하나로 했다.
- 전송(fetch)을 `link_*`마다 복사: 계약 규약이 여러 곳에 생겨 어긋난다. 주입으로 한 곳에 모았다.
- 컨트롤러를 컴포넌트로 취급: 상태가 있어 같은 입력 -> 같은 출력이 아니다.
- quicktype 등 다른 타입 생성기: DESIGN.md가 json-schema-to-typescript를 지정한다. 다른 도구를 비교하지 않았다.

## 결과
- 얻는 것: 거부 조건이 스키마에 모였고(예외 5건은 `schemas/README.md`), 컴포넌트를 DOM·HTTP 없이 시험할 수 있다. 구조 검사가 시험으로 강제된다.
- 감수하는 것: 파일 수가 늘었다(스키마 55개, 컴포넌트 24개). 생성된 타입은 `allOf`/`minItems` 때문에 튜플·교차 타입이 어색하다(`evidence_refs: [string, ...string[]]`). 번들 크기 변화는 측정하지 않았다. 검증이 스키마 해석 코드를 거치므로 속도 변화도 측정하지 않았다.

## 되돌리는 조건
계약이 브라우저용 타입·검증기를 배포하면 생성 단계를 그것으로 바꾼다. 헤드의 구조 검사가 `ui/`를 허용하면 `wiring/ui/`를 `ui/`로 올린다.
