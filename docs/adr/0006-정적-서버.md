# ADR 0006: 의존 없는 Node 정적 서버(`serve/static-server.mjs`)

- 상태: 채택

## 맥락
이미지는 빌드된 정적 파일을 내보내고 `/healthz`·`/readyz`(워크스페이스 규약), 개발용 `/config.json`을 제공해야 한다. `/v1`은 배포의 게이트웨이가 같은 출처로 프록시하므로 이 서버는 처리하지 않는다. 비밀은 없다.

## 결정
`node:http`만 쓰는 100줄 미만 서버를 직접 둔다. 모든 응답에 `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, CSP(`default-src 'self'`, `script-src 'self'`, `frame-ancestors 'none'` 등)를 붙인다. GET/HEAD만 허용하고 경로 탈출을 막는다. 포트는 `PORT`(기본 8080), root가 아닌 `node` 사용자.

## 왜
- 설계서 6절 "작은 정적 서버(의존 없음)". 이미지에 npm 런타임 의존이 없어 잠금·감사 대상이 줄고, 헤더·`/healthz`·`/config.json`이 한 파일에서 보인다.
- `no-store`: 보고서·사례 내용이 브라우저·중간 캐시에 남지 않게 하려는 것(브리프 4절 "저장소에 남기지 않는다"의 연장). 정적 자산에도 붙인 것은 단순함을 우선한 것이고 성능은 **측정 안 함**.
- CSP는 인라인 스크립트·외부 출처를 막아 XSS 피해를 줄이는 표준 방어다(번들이 `script-src 'self'`로 도는지 **실제 브라우저에서는 확인하지 못했다**, STATUS 남은 일).

## 검토한 대안과 버리는 이유
- nginx/Caddy 이미지: 설정 파일과 베이스 이미지가 늘어난다. 이 대안과 비교한 기록은 없다(근거 기록 없음). 위 이유는 구조에서 도출한 것이다.
- `npm start`용 dev 서버를 이미지에 넣기: 개발 의존이 이미지에 들어가므로 버림.

## 결과
- 얻는 것: 작은 이미지, 의존 0. 감수하는 것: 압축·ETag·Range 같은 기능이 없다(내부 소수 사용자 화면이라 필요하다고 보지 않았으나 부하는 측정 안 함).

## 되돌리는 조건
정적 서빙에 압축·캐시 제어가 필요하거나 게이트웨이가 정적 파일도 서빙하게 되면 이 서버를 없앤다.
