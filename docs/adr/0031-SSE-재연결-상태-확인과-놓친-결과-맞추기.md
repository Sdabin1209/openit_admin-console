# ADR 0031: SSE가 닫히면 알림 목록 읽기로 상태를 확인하고, resync는 updated_after로 맞춘다

- 상태: 채택(2026-11-04, 계약 v3.4.6 PUBLIC_API 직원 콘솔 표 SSE 행·B절)

## 결정
- `EventSource`가 CLOSED면 `GET /v1/staff/alerts?status=OPEN&limit=1`을 한 번 불러 상태와 `Retry-After`만 읽는다(구독이 아니라서 `staff_alert` 전달 판정에 세지 않는다). 401은 로그인 안내, 429·503은 `Retry-After` 뒤, 그 밖은 지수 백오프(1초에서 두 배, 상한 30초: 계약에 값이 없어 정한 시작값, 측정 안 함)로 새로 연결한다.
- `heartbeat`의 `ts`를 기억하고 `resync`를 받으면 `GET /v1/results?updated_after=<ts>`로 놓친 변경만 가져와 목록에 합친다. heartbeat가 없으면 첫 쪽을 다시 읽는다.
- 화면 대기 상한은 결과·푸시·로그인 확인 경로 60초(계약 시간 상한 사슬의 표에 행이 없는 사람 경로). 이전 70초는 계약에 없는 값이라 ADR 0024의 해당 값을 대체한다.

## 왜
계약 문장 그대로다. 같은 경로를 구독으로 다시 열면 서버가 구독자로 세어 위험 알림이 읽히지 않는데 전달됐다고 판정될 수 있다.

## 되돌리는 조건
계약이 상태 확인 방법을 바꾸면 따른다.
