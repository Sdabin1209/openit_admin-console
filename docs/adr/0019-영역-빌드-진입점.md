# ADR 0019: 영역 빌드 진입점 `scripts/build-image.sh`

- 상태: 채택(U42, 계약 v2.5.0). ADR 0017의 검증기 생성을 이어 쓴다.

## 맥락
deploy의 `build-images.sh`가 이 영역 Dockerfile의 인자 이름(`REVISION`, `BOUNDARY_CONTRACTS`, `SURVEY_SCHEMA`)과 빌드 컨텍스트 만드는 법을 직접 알았다(구조 규칙 1 위반, OPEN_GAPS U42). 계약 v2.5.0이 영역 빌드 진입점(`BuildImageRequest`/`BuildImageResult`)을 정했다.

## 결정
- `bash scripts/build-image.sh <요청 JSON>`이 얇은 껍데기이고 본체는 `scripts/build-image.mjs`다. 요청을 계약 검증기(`BuildImageRequest`)로 검사하고, 리포 루트를 컨텍스트로 `docker build`(진행은 표준 오류)를 한 뒤, `docker image inspect`로 읽은 `io.openit.*` 라벨을 `ImageLabels`로 검사하고, `BuildImageResult` 한 줄을 표준 출력 마지막 줄에 낸다.
- 이 영역이 쓰는 입력은 `revision`, `versions.boundary`, `image_tag`뿐이다. `dependency_sources`는 쓰지 않는다(이미지에 이웃 소스를 넣지 않는다. 계약 검증기는 생성물로 이미 리포에 있다, ADR 0002). `variant`가 오면 실패한다(변형 없음). `source_dir`이 이 리포 루트가 아니면 실패한다.
- 라벨 `survey-schema`, `turn-engine`, `model-runtime`은 `n/a`다(소비하지 않음). `ImageLabels`가 `n/a`를 허용한다.
- 생성 검증기에서 `require("ajv/dist/runtime/ucs2length")`를 같은 함수의 인라인으로 바꿨다(`gen-schemas.mjs`).

## 왜
- 계약 2.5.0의 BuildImageRequest/Result 설명이 정본이다. 라벨은 요청을 되풀이하지 않고 이미지에서 읽는다(계약: "이미지에 실제로 붙은 라벨"). Dockerfile이 인자를 라벨로 옮기지 않는 사고를 요청 값과 대조해 잡는다.
- 본체를 Node로 둔 이유: 계약 검증기가 이미 Node(Ajv standalone)로 생성돼 있어 같은 도구로 검사하고, Python 환경을 이 영역에 새로 요구하지 않는다. 대안(bash+jq 손 검사)은 R6·ADR 0017에 어긋난다.
- 인라인 이유: 진입점이 deploy 호스트에서 `npm ci`(네트워크) 없이 `node`만으로 돌아야 한다(계약: 빌드 중 네트워크 대신 dependency_sources). 인라인한 함수는 ajv 8.20.0의 12줄(MIT)이다. ajv를 올릴 때 생성기가 호출 문자열을 못 찾으면 실패하도록 해 조용히 어긋나지 않게 했다.
- Dockerfile ARG 기본값(`BOUNDARY_CONTRACTS`)은 남겼다. 스모크가 읽는 기본값일 뿐이고 deploy는 요청으로 덮어쓴다. 계약 핀을 올릴 때 이 값과 생성 검증기를 함께 올린다.

## 검토한 대안과 버리는 이유
- 껍데기 없이 `node scripts/build-image.mjs`만: 계약이 `bash scripts/build-image.sh`를 정했다.
- `docker build` 안에서 검증: 요청 검증이 빌드 뒤로 밀리고 오류가 늦게 난다.

## 결과
- 얻는 것: deploy가 이 영역의 Dockerfile 인자를 모른다. 스모크가 같은 진입점으로 빌드해 매 변경마다 확인한다.
- 감수하는 것: 호스트에 node(24 이상)가 필요하다(`package.json` engines; 이전엔 docker만 필요했다). 빌드 컨텍스트는 `source_dir`의 작업 트리이고 `.dockerignore`를 따른다. deploy가 이전처럼 `git archive`한 깨끗한 트리를 주면 같다. 멱등: `docker build --provenance=false`를 쓴다(BuildKit 출처 증명이 ID를 매번 바꾼다. 끄기 전에는 같은 입력에서 image_id가 달랐고, 끄고 두 번 빌드해 같은 ID를 확인했다). 이 플래그를 모르는 오래된 docker에서는 빌드가 실패한다.

## 되돌리는 조건
계약 진입점이 바뀌면(3.0.0에서 `turn_engine` 삭제 등) 이 ADR을 대체한다.
