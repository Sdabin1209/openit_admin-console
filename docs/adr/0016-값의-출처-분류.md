# ADR 0016: 이 영역의 숫자 값은 어디서 왔는가(출처 분류)

- 상태: 채택(2026-10-29, 표준성 점검 N- 항목, 헤드 결정표 2절 "전 영역"). 값은 바꾸지 않았다. 이 ADR은 [ADR 0010](0010-시간-제한과-한도-상수.md)의 표를 이어받아 점검에서 새로 찾은 값을 더하고 출처를 분류한다.

## 맥락
점검(`docs/audit/standards-2026-10-29.md`)에서 근거 없는 값이 여럿 나왔다. 근거를 지어내지 않고, 값마다 출처가 측정·표준·제약 중 무엇인지, 아니면 없는지를 적는다.

## 분류
출처 칸의 뜻: **제약** = 계약·플랫폼이 정한 값, **표준** = 이름 있는 표준이 정한 값, **측정** = 이 영역이 잰 값, **없음** = 정한 이유를 기록하지 못한 임의의 초기값. **어떤 값도 측정하지 않았다.**

| 값 | 위치 | 출처 | 비고 |
| --- | --- | --- | --- |
| 목록 쪽 크기 500 | `api/cases.ts`, `api/releases.ts` | 제약 | 계약 HTTP.md 공통 목록 규칙의 limit 최대 |
| 승인 목록 쪽 크기 100 | `api/client.ts` | 제약 | 같은 규칙의 limit 기본값 |
| 목록 최대 20쪽(1만 건) | `api/cases.ts`, `api/releases.ts` | 없음 | 서버 오류로 끝없이 읽는 것을 막는 방어 상한. 실제 사례·릴리스 수를 측정하지 않았다. 넘으면 오류(ADR 0013) |
| 요청 시간 제한 15000ms | `api/http.ts` | 없음 | 게이트 응답 시간 분포를 측정하지 않았다. 헤더만 오고 본문이 멈추는 경우를 막는 것이 목적(방식은 `AbortController`, WHATWG DOM) |
| 보고서 해시 표시 19자 | `app/views.ts` | 없음 | 사람 눈 대조용 앞부분. 전송 값은 전체 해시 |
| 검증 오류 표시 최대 8건 | `app/validate.ts` | 없음 | 화면에 한꺼번에 보이는 오류 수를 줄이려는 값. 측정·사용성 조사 안 함 |
| 시험 조건 대기 상한 15000ms | `tests/helpers.ts` | 없음 | 통과 조건이 아니라 실패 상한. 부하에서 오래 걸려도 실패하지 않게 넉넉히 잡았다. 측정 안 함 |
| 모의 서버 지연 300ms(`slowMs` 기본) | `mock-server/server.ts` | 없음 | 느린 응답 시나리오용. 시험은 150ms를 주입한다 |
| `npm ci` 재시도 1회, 대기 5초 | `scripts/setup-env.sh` | 없음 | 일시적 네트워크 장애 대비라는 목적만 있고 횟수·시간은 임의 |
| 번들 target `es2022` | `scripts/build.mjs` | 없음 | 지원 브라우저 기준을 정하지 않았다. `<dialog>.showModal`, CSS `color-mix` 등을 쓰므로 최신 브라우저가 전제이며 어느 버전부터인지 확인하지 않았다 |
| 이미지 포트 8080 | `Dockerfile`, `serve/Caddyfile` | 제약 | 워크스페이스 규약(`/healthz` 스모크가 호스트 포트를 Docker에 맡김) |

## 왜 값을 바꾸지 않는가
측정 없이 숫자를 다른 숫자로 바꾸면 근거 없는 값만 새로 생긴다. 출처가 "없음"인 값은 측정 계획을 아래에 적고 측정하면 이 표를 고친다.

## 측정 계획(하지 않았다, 조건만 적는다)
- 요청 시간 제한: 운영에서 게이트 `/v1` 응답 시간 분포가 생기면 상위 분위수를 근거로 값을 다시 정한다. 운영 전에는 측정할 수 없다.
- 20쪽: 운영에서 릴리스·실패 사례 수가 생기면 현실적 상한을 정한다. 상한 접근 시 서버 쪽 필터를 계약에 요청한다(ADR 0013).
- es2022 target: 운영팀이 쓰는 브라우저 목록을 받으면 browserslist 기준으로 정한다.

## 되돌리는 조건
값을 측정하거나 표준·계약에서 근거를 찾으면 이 표의 해당 행을 고치고, 값이 바뀌면 새 ADR로 대체한다.
