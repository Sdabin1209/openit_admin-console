# ADR 0018: 정적 서버를 Caddy file_server 이미지로 한다

- 상태: 채택(단위 4a, D111). 대체한다: [ADR 0006](0006-정적-서버.md)(직접 만든 Node 정적 서버).

## 맥락
이미지는 빌드된 정적 파일, `/healthz`·`/readyz`, 보안 헤더를 내야 한다. ADR 0006은 100줄 미만의 `node:http` 서버를 직접 두었고, 대안(nginx/Caddy)과의 비교 기록이 없었다. 직접 만든 서버는 압축·ETag·Range·연결 제한·느린 클라이언트 처리를 갖지 않고, 그것을 갖추려면 표준 서버가 이미 하는 일을 다시 만들게 된다.

## 결정
`caddy:2.11.7-alpine`(정확한 태그)에 `serve/Caddyfile`과 `dist/`(`/srv`)를 넣는다. 직접 만든 `serve/static-server.mjs`와 `npm start`는 지웠다. 보안 헤더 값, `/healthz`·`/readyz` 본문(`{"status":"ok"}`), GET/HEAD 외 405, 없는 경로 404 `not found`(보안 헤더 유지)는 그대로다. `/config.json`은 ADR 0012에서 이미 없어졌으므로 옮길 것이 없다. 비root(uid 65532), 포트 8080, 로그는 표준 출력(Caddy `log` 출력 stdout).

## 왜
- 표준 도구의 설정으로 같은 성질을 얻고 자체 코드를 없앤다(D111). 배포의 게이트웨이도 Caddy라 도구가 하나로 모인다.
- 설정 값의 출처:
  - `admin off`, `auto_https off`, `persist_config off`: 제약. 이 이미지는 TLS를 끝내지 않고(게이트웨이 몫) 관리 API가 필요 없다. 열어 두면 공격면만 는다.
  - 헤더 값(`no-store`, `nosniff`, `no-referrer`, CSP): ADR 0006에서 옮긴 것. 근거는 거기에 있다.
  - 포트 8080: 워크스페이스 규약(비특권).
  - 연결 상한·읽기 timeout 등은 Caddy 기본값을 쓴다. 바꾸지 않았고 부하는 **측정 안 함**.
- 동작이 같다는 근거: `tests/static-behavior.test.ts`가 구현과 무관한 동작 시험이다. 직접 만든 서버에서 7개 통과(2026-10-29), 이미지에서도 7개 통과(`npm run smoke`가 이미지에 대해 돌린다).

## 검토한 대안과 버리는 이유
- 직접 만든 Node 서버 유지: 위 맥락. 유지 비용이 이득보다 크다고 판단했고 부하 비교는 측정 안 함.
- nginx: 같은 일을 하지만 게이트웨이가 Caddy라 도구가 둘이 된다. 성능 비교는 하지 않았다.

## 결과
- 얻는 것: 표준 서버의 기능(압축 가능, 정적 파일 처리의 검증된 구현), 자체 코드 0.
- 감수하는 것: 이미지가 Node alpine보다 크다(크기는 측정 안 함). 새 베이스 이미지의 취약점 추적이 필요하다. 기본 `caddy:2-alpine` 부동 태그가 아니라 정확한 태그를 써서 갱신은 수동이다.
- 동작 차이: 응답의 `Server` 헤더를 지웠다(원래 없었다). `HEAD /healthz`처럼 바디 없는 요청 외에 관찰되는 차이는 시험으로 찾지 못했다.

## 되돌리는 조건
게이트웨이가 정적 파일까지 서빙하게 되면 이 이미지를 없앤다.
