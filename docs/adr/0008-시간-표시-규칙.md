# ADR 0008: 시각은 UTC 원문에 현지 시각을 병기한다

- 상태: 채택(작업 단위 6, 전수 점검 지적)

## 맥락
계약의 `Timestamp`는 UTC 문자열(예: `2026-10-14T00:00:00Z`)이다. 운영자는 한국 시간으로 읽고, 근거 로그·서버 기록과 대조할 때는 UTC 원문이 필요하다.

## 결정
`app/time.ts`의 `fmtTime`이 `원문 (현지 YYYY-MM-DD HH:mm TZ)` 형식으로 보인다. 시간대는 브라우저 설정을 따르고 시험은 시간대를 명시해 결정적으로 만든다. 해석할 수 없는 값은 원문만 보인다.

## 왜
- 서버 기록과 같은 문자열을 화면에서도 볼 수 있어야 대조가 정확하다(원문 보존). 현지 시각은 읽기 편의다.
- 표준: 서버 쪽 형식은 계약의 `Timestamp`(RFC 3339 계열 UTC)이다. 현지 병기 형식은 `Intl.DateTimeFormat`(`sv-SE`)이 `YYYY-MM-DD HH:mm`을 내는 것을 이용한 것으로, 로캘 선택에 다른 근거는 없다(근거 기록 없음).

## 검토한 대안과 버리는 이유
- 현지 시각만: 서버 기록과 대조하기 어렵다. UTC만: 읽기 불편.

## 결과
브라우저 시간대가 잘못되면 현지 병기도 틀린다(원문은 맞다).

## 되돌리는 조건
운영팀이 고정 시간대(예: KST 고정)를 요구하면 시간대를 설정으로 받는다.
