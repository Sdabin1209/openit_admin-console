# ADR 0026: 의사용 "문진 결과" 화면은 이 콘솔 안의 탭으로 둔다

- 상태: 채택(2026-11-03, U83, 사용자 결정: 문진 결과는 의사가 본다. 계약 v3.2.0 PUBLIC_API B).

## 맥락
의사가 문진 결과(목록, 상세, 인쇄, 확인 표시)를 보고 새 결과 도착을 알림으로 받아야 한다. 계약 PUBLIC_API B가 이 화면을 "admin-console 의 문진 결과 탭"으로 정했고 게이트웨이는 읽기·확인 표시 경로를 `clinician` 계정에만 연다.

## 결정
- 기존 SPA에 탭(`#/results`, `#/results/{session_id}`)을 더한다. 별도 앱·이미지는 만들지 않는다.
- 통신 컴포넌트 4개(`link_result_list`, `link_result_get`, `link_result_ack`, `link_result_events`)와 업무 컴포넌트 1개(`result_sheet`), 컨트롤러 `results_controller`, 화면 `ui/results_view`.
- 도착 알림은 직원 SSE `GET /v1/staff/alerts/stream`의 `result_ready`를 앱 시작 때 한 번 구독한다. 목록을 보는 중이면 첫 쪽을 다시 읽고, 다른 화면이면 탭 배지 수를 올린다. 끊겼다 다시 열리면 목록을 다시 맞춘다(계약의 resync와 같은 방식).
- 응답은 읽기용 투영 스키마 `ResultRecord`로 검사한다(모르는 상태·사유 코드·필드는 받는다). 문진 스키마 SessionResult에 대한 적합성은 시험이 `../survey-service/schema`(읽기 전용)로 모의 출력을 검사한다.
- 화면 대기 상한 70초(`RESULTS_TIMEOUT_MS`): CONVENTIONS "시간 상한 사슬"의 gateway 직원 경로 56초 위에 10초 여유(ADR 0024와 같은 방식). 이 경로의 gateway 설정값은 확인하지 못했고(추정), 측정하지 않았다.
- `deploy-exposure.json`의 화면 역할 목록에 `clinician`을 더했다. 정적 화면은 인증된 어느 계정에게나 열리고(ADR 0021) 이 이미지는 `/v1`을 처리하지 않으므로, 노출 선언은 화면을 쓰는 역할을 적는 것뿐이다.

## 왜
- 별도 앱을 두면 인증(게이트웨이 계정 로그인, `X-Openit-User` 부착), 이미지 빌드·라벨·스모크, deploy 노출 선언과 배포가 앱마다 둘이 된다. 같은 정적 서버, 같은 출처 `/v1`, 같은 헤더 규칙을 그대로 쓰는 편이 표면이 작다.
- 계약이 이미 "admin-console 의 탭"이라고 정했다.
- 한 쪽만 읽는 이유(목록): 결과는 세션마다 쌓이고 의사는 최신부터 본다. 릴리스 목록처럼 끝까지 읽으면 느리고 이득이 없다. 쪽 크기 50은 계약 limit 기본값이다(제약에서 온 값).
- 판단하지 않는다: 화면은 완료 여부를 `status == ENDED_COMPLETE`로만 알리고(계약 문장), 완료가 아니면 부분 결과임을 알린다. 빈칸 사유 코드는 코드와 뜻을 함께 보인다.
- 확인 표시의 중복 클릭은 컨트롤러가 한 번만 보내고, 이미 확인됐으면 버튼을 잠근다. 서버도 멱등이다(계약).
- 인쇄는 브라우저 인쇄와 `@media print` 스타일(메뉴·버튼 숨김)만 쓴다. PDF 생성 의존을 두지 않는다.

## 검토한 대안과 버리는 이유
- 별도 의사용 앱: 위 이유. 인증·배포가 둘이다.
- 폴링으로 도착 확인: 계약이 SSE를 정했고, 폴링은 지연과 요청이 는다. 비교 측정은 하지 않았다.
- 계약 SessionResult 검증기를 직접 생성: 문진 스키마는 이 영역이 고정한 태그가 없고(Dockerfile `SURVEY_SCHEMA=n/a`) `acknowledged_by/at`이 아직 그 스키마에 없다(CR-007). 엄격한 검증기는 확인된 결과를 거부한다. 그래서 읽기용 투영 + 적합성 시험으로 했다.

## 결과
- 얻는 것: 탭 하나로 의사 화면 완성, 새 결과가 오면 자동 갱신, 배포 표면 그대로.
- 감수하는 것: 한 이미지가 의사용 화면까지 싣는다(역할 제한은 게이트웨이 경로 몫). 실제 survey-service와 실제 브라우저 EventSource(재연결, Last-Event-ID)로는 확인하지 못했다. 시험의 EventSource는 fetch로 SSE 줄을 읽는 대용품이다. `result_ready`가 어느 계정에게나 가는지(clinician 이외 403)는 모의 서버 기준이다. 키 `Q7_1[soju].amount`를 문항과 칸으로 나누는 규칙(`[` 앞이 문항)은 문항 ID 형식을 모르는 상태의 추정이다.

## 되돌리는 조건
결과 화면의 사용자가 늘어 배포·권한을 따로 해야 하거나, 화면이 두 배 이상 커지면 별도 앱으로 나누는 새 ADR을 쓴다. 문진 스키마가 태그로 고정되고 ack 필드가 들어오면 투영 대신 생성 검증기로 바꾼다.
