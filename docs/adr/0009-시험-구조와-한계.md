# ADR 0009: node:test + jsdom, 실제 브라우저 시험 없음

- 상태: 채택. 실제 브라우저 시험 부재는 알려진 한계.

## 맥락
화면 로직과 DOM 그리기를 자동으로 확인해야 하고, 이웃 없이 혼자 돌려야 한다. 간헐 실패가 한 번 있었다(고정 대기 때문: 작업 단위 6).

## 결정
- 러너는 Node 내장 `node:test`(Node 24가 TypeScript를 직접 실행). DOM 그리기는 `jsdom`에서 돌린다. 컨트롤러·클라이언트는 DOM 없이 시험한다.
- 비동기 결과는 조건 대기 `waitFor`로 기다리고(시간은 실패 상한일 뿐), 시계·타이머·요청 ID는 주입해 고정한다. 시험마다 공유 JSDOM의 화면을 비운다.
- 계약 스키마·예제는 `../boundary-contracts`(읽기 전용)에서 읽는다. 이 폴더가 없으면 일부 시험은 건너뛰거나 실패한다.

## 왜
- 의존 최소(ADR 0001): 러너를 추가하지 않는다. jsdom은 DOM 단언에 쓰는 개발 의존이다.
- 실제 시간에 기댄 단언은 부하에서 깨졌다. 재현: CPU 부하 병렬 4x10회 중 14회 실패, 순차 20회는 0회(작업 단위 6 기록). 그래서 가짜 시계·조건 대기를 쓴다.

## 검토한 대안과 버리는 이유
- Playwright 등 실제 브라우저: 레이아웃·키보드·CSP 아래 번들 실행을 볼 수 있으나 브라우저 설치와 CI 이미지가 필요하다. 비용을 측정하지 않았고, 도입 여부를 결정한 기록도 없다(근거 기록 없음).
- Jest/Vitest: 러너 의존 추가. `node:test`로 충분했다.

## 결과와 한계
- 한계(확인): jsdom은 레이아웃·포커스 이동의 실제 브라우저 동작·`<dialog>`의 모달 포커스 규칙·스크린리더를 검증하지 못한다. CSP 아래 번들 실행, 접근성 도구 검사, 키보드 흐름은 **확인하지 못했다**. 확인창 첫 포커스(ADR 0004)도 jsdom에서 `focus()` 호출 결과만 본다.
- 이웃 폴더 의존: 위 `../boundary-contracts`.

## 되돌리는 조건
화면 결함이 jsdom 밖(레이아웃·포커스)에서 나오기 시작하면 실제 브라우저 시험을 추가한다.
